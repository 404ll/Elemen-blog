## 1. 背景

当前站点已经具备 MDX 内容、分类列表、文章详情、目录、阅读进度、代码复制、代码练习和 Git 发布链路，但整体仍以“按时间发布文章的个人博客”为中心。

本次改造希望把站点定义为一个持续生长的个人知识库：既方便公开阅读，也方便站点所有者快速记录问题、逐步整理理解，并让知识条目之间形成可发现的关系。

用户已明确的偏好：

- 保持简洁，但不能退化成没有个人气质的文档站。
- 页面美感是核心质量要求，不是实现完成后的装饰项。
- 使用可视化表达知识关系、学习路径和内容状态。
- 写入流程要比手工维护 frontmatter 和发布命令更轻松。
- UI、产品结构和实现决策都必须在仓库中留下可追溯 SPEC。

## 2. 与旧设计规格的关系

本 SPEC 在产品定位和全站信息架构层面，替代 [`2026-04-30-blog-redesign-design.md`](./2026-04-30-blog-redesign-design.md)。旧规格中已经实施且仍有价值的内容可以保留，但不再把以下内容视为新设计的硬约束：

- 所有卡片必须使用不规则手绘边框。
- 全站以暖橙渐变作为主要视觉背景。
- 所有标签必须使用同一种方形等宽样式。
- 文章详情必须延续大卡片式容器。

旧规格中继续有效的原则：

- 装饰需要克制。
- 等宽字体主要用于代码和元数据。
- 通过线条、留白和排版建立层次，减少重阴影。
- 暗色模式和移动端响应式不能退化。

## 3. 产品定义

### 3.1 一句话定位

一个公开可阅读、由 MDX 和 Git 驱动、能够持续整理与连接个人理解的知识库。

### 3.2 内容层级

```text
Personal Knowledge Base
├── Topic             知识主题
├── Learning Path     学习路径
├── Knowledge Note    概念、问题、排障、实践记录
├── Article           整理完成的长文章
└── Practice          代码练习与工作收集
```

博客不会消失，而是成为知识库中的一种较完整内容形态。内容可以沿着以下生命周期成长：

```text
快速记录 → 知识条目 → 持续补充 → 长文章 / 学习路径节点
```

### 3.3 核心用户任务

读者需要能够：

1. 通过搜索快速找到一个问题、概念或实践记录。
2. 通过主题和学习路径理解内容之间的关系。
3. 长时间阅读正文而不被装饰和工具打扰。
4. 从一篇内容自然进入前置知识、相关内容和下一步学习。

站点所有者需要能够：

1. 快速创建草稿，不必先完成完整文章结构。
2. 在真实站点样式下预览 MDX。
3. 管理 frontmatter、图片、关联内容和发布状态。
4. 在发布前得到明确的验证结果。

## 4. 设计原则

### KB-PRINCIPLE-001 内容优先

排版、留白和层级先保证内容可读；视觉元素不能抢走正文注意力。

### KB-PRINCIPLE-002 可视化必须表达真实信息

知识图、节点、进度线和状态标记必须对应真实内容模型。禁止为了“看起来像知识库”而显示虚构统计或没有导航作用的图表。

### KB-PRINCIPLE-003 美感来自系统一致性

字体角色、色彩、间距、边框、动效和图形语言必须形成统一系统。避免依靠大量独立插图、渐变和卡片特效制造美感。

### KB-PRINCIPLE-004 阅读界面与写作界面分工

公开阅读页可以具有个人视觉表达；本地写作工作台优先保证速度、密度、反馈和可恢复性。

### KB-PRINCIPLE-005 渐进迁移

现有 53 篇 MDX 和既有 URL 必须继续工作。新增字段提供默认值，不要求一次性重写全部历史内容。

### KB-PRINCIPLE-006 可访问且克制的动效

动效只用于表达焦点、状态和关系，优先使用 `transform` 与 `opacity`，并支持 `prefers-reduced-motion`。

## 5. 信息架构

### 5.1 建议主导航

| 导航 | 目标 | 说明 |
|---|---|---|
| 知识库 | `/knowledge` 或兼容现有 `/blog` | 全部可公开知识条目的索引 |
| 学习路径 | `/paths` | 按顺序组织的学习主题 |
| 代码练习 | `/practice` | 保留现有练习模块 |
| 关于 | `/about` | 个人介绍和站点说明 |

在对应页面完成前，不展示没有实际路由的“资源分享”等入口。

### 5.2 首页

首页不再展示一个带内部滚动条的完整文章列表。首屏和第二屏按以下优先级组织：

1. 站点定位和全局搜索。
2. 少量可交互的知识主题概览。
3. 最近更新，而不是只看首次发布时间。
4. 正在学习的路径。
5. 代码练习和快速入口。

### 5.3 知识索引

索引需要支持：

- 搜索标题、摘要、别名、正文标题、正文内容和标签。
- 按主题、类型、状态过滤。
- 按最近更新、首次发布排序。
- 将查询条件写入 URL，允许保存和分享当前视图。
- 使用轻量列表而不是高阴影宣传卡片。

### 5.4 文章详情

保留目录、阅读进度、返回顶部和代码复制，增加：

- 主题、类型、内容状态。
- 创建时间和更新时间。
- 前置知识、相关内容、反向链接。
- 所属学习路径及当前位置。
- 上一篇、下一篇或自然的继续阅读入口。

文章正文在桌面端保持约 `68ch–72ch` 的稳定行宽；移动端不得出现正文横向滚动，代码块和表格除外。

## 6. 视觉系统方向

### 6.1 方向定义

已确认方向为“克制的编辑式知识界面”：使用编辑式内容骨架、强排版、模块网格和充足留白，并在局部加入具有真实信息含义的知识关系可视化。

Dribbble 仅作为视觉语言和构图参考，不直接复制具体作品、品牌资产或界面结构。详细取舍见[视觉参考](./2026-07-17-personal-knowledge-base-redesign-references.md)。

### 6.2 字体角色

- Logo / 品牌短文本：允许保留 Bitcount，建立个人辨识度。
- 中文正文：使用适合长文阅读的中文无衬线字体栈。
- 代码和元数据：使用 JetBrains Mono。
- 不再让全站正文继承等宽字体。

### 6.3 色彩

浅色版采用中性底色，橙色作为主要强调色。具体色值在首页视觉稿评审中收敛，但必须满足：

- 中性背景承担大部分页面面积。
- 主强调色使用橙色；第一版不引入与橙色竞争的大面积辅助色。
- 分类不依赖“每类一种鲜艳颜色”区分。
- 颜色不作为传达状态的唯一方式。
- 当前先完成浅色版；暗色版在浅色视觉语言确认后派生，并满足正文和交互控件的可读对比度。

### 6.4 表面和层次

- 默认使用留白、细边框和背景明度差建立层次。
- 阴影只用于真正浮在内容上方的元素，例如菜单、弹层和移动端抽屉。
- 控制圆角数量，避免所有内容都变成相同的 SaaS 卡片。
- 正文页比首页更安静；写作工作台比正文页更工具化。

### 6.5 可视化元素

优先级从高到低：

1. 学习路径进度和当前位置。
2. 主题数量、最近更新和关联强度。
3. 内容状态和更新时间。
4. 文章的前置、相关和反向链接。
5. 小型知识关系图。

大型力导向知识图谱不是第一阶段目标。移动端必须降级为可扫描的列表或树状结构。

## 7. 内容模型

现有 frontmatter 保持兼容，逐步增加：

```yaml
type: learning-note
status: growing
topics:
  - browser
  - dom
path: understanding-browser
related:
  - frontend/dom-text-node
aliases:
  - DOM 选区
updatedAt: "2026-07-17"
```

建议字段：

| 字段 | 用途 | 是否第一阶段必需 |
|---|---|---|
| `type` | article / concept / learning-note / debugging | 是，允许默认值 |
| `status` | seedling / growing / evergreen | 是，允许默认值 |
| `topics` | 多主题归属 | 是 |
| `updatedAt` | 最近更新时间 | 是 |
| `path` | 学习路径 | 否 |
| `related` | 主动关联 | 否 |
| `aliases` | 搜索别名 | 否 |

## 8. 写作体验

### 8.1 第一阶段：增强命令行写作流程

- 新文章默认 `draft: true`。
- 标题自动生成可编辑 slug。
- 支持学习笔记、排障记录、工程实践和普通文章模板。
- 创建文章时同时创建图片目录。
- 提供单篇预览、单篇检查和发布前检查命令。

### 8.2 后续阶段：本地 Writing Studio

本地工作台可以提供：

- 草稿和已发布内容列表。
- frontmatter 表单。
- MDX 编辑和真实样式预览。
- 自动保存与未保存离开提醒。
- 图片拖入和路径插入。
- 搜索并建立关联内容。
- 发布前验证。

第一版保持 local-first，MDX 与 Git 继续作为事实来源。不在尚未明确远程写作需求前引入数据库或远程 CMS。

## 9. 分阶段范围

### Phase 0：规格与设计基线

- [ ] 本 SPEC 获得确认。
- [ ] 核心页面建立当前状态截图或可复现基线。
- [ ] 确认视觉方向和设计 tokens。
- [ ] 为首页、知识索引、文章详情生成并评审桌面与移动端设计稿。

### Phase 1：阅读基础与全局外观

- [ ] 修正正文中文字体、行宽、字号和行高。
- [ ] 清理失效导航和首页内部滚动。
- [ ] 文章列表改为轻量、可扫描、标题可点击的索引。
- [ ] 修正中文阅读时间。
- [ ] 完成基础可访问性和 reduced-motion 支持。

### Phase 2：知识库信息架构

- [ ] 扩展内容模型，同时兼容旧 frontmatter。
- [ ] 主题、类型、状态和更新时间筛选。
- [ ] 最近更新、相关内容和学习路径。
- [ ] 构建期全文搜索和 URL 状态同步。

### Phase 3：写作体验

- [ ] 增强 `new-post`。
- [ ] 提供单篇预览与发布检查。
- [ ] 评估并实现本地 Writing Studio。

## 10. 非目标

- 第一阶段不建设大型知识图谱。
- 不为了视觉效果生成虚构阅读量、知识数量或学习进度。
- 不一次性迁移或重写全部旧文章。
- 不在需求未明确前接入用户系统、数据库或重型 CMS。
- 不直接复刻 Dribbble 作品。
- 不在设计稿批准前进行全站视觉实现。

## 11. 验收标准

### 阅读体验

- [ ] 中文正文不使用等宽字体。
- [ ] 桌面正文主要段落行宽保持在 `68ch–72ch`。
- [ ] 首页和文章列表不存在嵌套主滚动区域。
- [ ] 所有主要交互都有键盘可见焦点。
- [ ] 移动端可以完成搜索、筛选、阅读和目录导航。

### 视觉质量

- [ ] 设计评审包含桌面和移动端稿。
- [ ] 每个可视化元素都能映射到真实字段或真实导航关系。
- [ ] 页面不依赖重阴影、玻璃拟态和大面积渐变建立层次。
- [ ] 首页、索引、文章页和写作工作台共享同一套 tokens，但具有清楚的密度差异。

### 写作体验

- [ ] 新草稿默认不会进入公开文章列表。
- [ ] 新建文章不需要手动拼写完整 frontmatter。
- [ ] 发布前能明确看到内容、链接、图片和构建验证结果。
- [ ] 写作输出仍然是可版本管理的 MDX 文件。

### 兼容性

- [ ] 现有公开文章 URL 不失效。
- [ ] 未包含新字段的旧文章可以正常构建和展示。
- [ ] `/practice` 模块和 submodule 工作流不退化。

## 12. 追踪规则

从本 SPEC 开始，所有知识库改造遵循以下规则：

1. 每个实现任务引用一个 SPEC 需求编号或 Phase 条目。
2. 视觉稿按 `concept-vN`、`home-vN`、`article-vN` 命名，不覆盖历史稿。
3. 被否决的稿件保留，并在决策日志中记录保留与否决原因。
4. 新的产品或视觉判断先更新决策日志，再进入实现计划。
5. 实现计划放在 `docs/superpowers/plans/`，并链接回本 SPEC。
6. 验证结果记录实际运行的命令、页面和设备尺寸，不使用笼统的“已测试”。

## 13. 开放问题

已确认：

1. 中性底色，橙色作为少量强调。
2. 首页使用编辑式内容骨架，并在局部加入知识关系可视化。
3. 先完成浅色版，暗色版在浅色定稿后派生。

仍待确认：

1. `/blog` 是否逐步更名为 `/knowledge`，或只改变页面呈现而保留 URL？
2. 写作工作台是否只需要本地使用，还是未来需要手机和远程浏览器写入？

这些问题未确认前，允许继续做探索稿，但不应进入不可逆的全站实现。
