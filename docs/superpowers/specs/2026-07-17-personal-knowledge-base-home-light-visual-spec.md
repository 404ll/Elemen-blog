## 1. 本轮目标

验证以下视觉方向是否成立：

- 中性浅色背景能否让页面更精致、稳定，并承载长时间阅读。
- 编辑式内容骨架能否取代 V1 的常见 Dashboard 卡片。
- 一个局部、真实的知识关系图能否成为视觉记忆点，而不压过内容。
- 首页是否可以同时表达“最近写了什么”和“知识如何连接”。

本轮先用首页切片验证视觉层级和整体气质，不决定暗色模式。实现范围见 [`../plans/2026-07-17-personal-knowledge-base-home-light-v2.md`](../plans/2026-07-17-personal-knowledge-base-home-light-v2.md)。

## 2. V1 问题基线

V1 [`concept-v1.png`](./assets/knowledge-base-redesign/concept-v1.png) 的问题：

- Hero 标题过大，首屏更像产品 Landing Page。
- 彩色圆形节点与矩形卡片形成常见 SaaS Dashboard 观感。
- 知识数量和学习百分比不是来自当前内容模型。
- 最近更新和学习路径被装进相同规格的面板，缺少编辑式节奏。
- 视觉结构依赖截图尺寸，移动端缺少清楚的降级方式。

V2 必须逐项修正这些问题。

## 3. 画布和网格

- 基准画布：`1536 × 1024`。
- 内容最大宽度：约 `1280px`。
- 使用 12 栏编辑式网格，栏间距约 `24px`。
- 顶部导航高度约 `64px–72px`。
- 页面左右留白不小于 `48px`；内容不贴边。
- 首屏允许露出下一段内容，避免整个页面像封闭 Dashboard。

## 4. 色彩方向

本轮建议色值用于探索，不作为最终 token：

| 角色 | 建议值 | 用途 |
|---|---|---|
| Canvas | `#F2F1ED` | 页面中性底色 |
| Surface | `#FBFAF7` | 少量需要区分的内容表面 |
| Ink | `#191916` | 标题、正文和主边框 |
| Muted | `#77746D` | 日期、辅助说明 |
| Hairline | `#D8D5CE` | 网格、分隔线、非活跃关系线 |
| Accent | `#F05A28` | 焦点、活跃状态、品牌标记 |

限制：

- 不使用蓝色作为第二主色。
- 不使用大面积渐变。
- 不使用玻璃拟态。
- 阴影只允许出现在浮层；首页内容区默认无阴影。

## 5. 字体角色

- Logo：保留少量像素或等宽性格，但尺寸收敛。
- 中文标题：清晰、有力量的无衬线字体，不使用夸张展示字体。
- 中文正文：系统中文无衬线字体。
- 英文标签、日期、数量：JetBrains Mono 或等价等宽字体。
- H1 桌面建议约 `48px–56px`，不得再次占据半个首屏高度。

## 6. 页面结构

### HOME-LIGHT-001 顶部导航

- 左侧：简短品牌标记 `Elemen / KB`。
- 中部：知识库、学习路径、代码练习、关于。
- 右侧：搜索入口与主题切换占位。
- 活跃状态使用细橙色线或小方形标记，不使用大面积填充。

### HOME-LIGHT-002 编辑式导语

- 小型英文或等宽 eyebrow：`PERSONAL KNOWLEDGE SYSTEM · 53 NOTES`。
- 主标题建议：`把问题写下来，让理解彼此连接`。
- 一句说明：`记录前端、AI、算法与工程实践中的真实问题。`
- 搜索入口需要明显，但不做成巨大产品搜索框。

`53` 来自当前仓库实际可发布文章数量，不得替换成虚构数据。

### HOME-LIGHT-003 最近更新

使用编辑式文章索引，而不是三张相同卡片。建议展示真实内容：

1. `Selection API 到划词高亮阅读器`
2. `Sitemap 动态生成与分片`
3. `X Viral Articles 数据链路`

每条显示：序号、标题、短摘要、分类、日期。第一条可以更突出，其余条目保持紧凑。

### HOME-LIGHT-004 局部知识关系

关系图只围绕一个真实主题展开：

```text
Selection API
├── Range
├── XPath
└── Text Node
    └── normalize()
```

规则：

- 使用细线、小节点和文本标签，不使用大型彩色圆形图标。
- 活跃节点使用橙色，其他节点使用墨色或灰色。
- 每个节点未来都应可以映射到文章内标题或独立知识条目。
- 不显示虚构相关度、百分比或阅读量。

### HOME-LIGHT-005 主题索引

使用仓库真实分类数量作为当前过渡数据：

- Frontend：37
- AI：9
- Algorithm：6
- Backend：1

主题索引以数字、文字和细线构成，不使用四色分类卡片。未来引入 `topics` 后，再从分类数量迁移到真实主题数量。

### HOME-LIGHT-006 正在整理

不显示虚构完成百分比。可以使用一个小型纵向路径表达当前文章中的理解推进：

```text
Selection → Range → XPath → normalize()
```

视觉状态只表达“当前聚焦”和“已存在内容”，不假装代表个人学习完成度。

## 7. 视觉细节

- 主要分隔使用 1px hairline。
- 圆角控制在 `0–12px`，不同内容不强制相同圆角。
- 最多使用一处轻量纸张纹理或坐标网格，透明度必须足够低。
- 允许极少量手写式橙色批注，但只能作为个人签名细节，不能承担导航。
- 图标统一使用线性图标；装饰图标不得代替文字标签。

## 8. 动效意图

设计稿只表达状态，不模拟复杂动画。未来实现时允许：

- 最近更新行 hover 时出现橙色左线。
- 关系节点聚焦时，仅相关连线增强。
- 搜索获得焦点时边框和快捷键提示变化。
- 动画只使用 opacity / transform，并提供 reduced-motion 降级。

## 9. 移动端降级原则

桌面方向确认后必须补移动端 SPEC 和设计稿。已知规则：

- 12 栏布局折叠为单列。
- 关系图转换为可点击树状列表，不强行缩小整张图。
- 最近更新保持列表，不改为横向轮播。
- 主题数量使用两列索引。
- 搜索保持首屏可见。

## 10. V2 验收标准

- [ ] 第一眼感受是个人编辑式知识库，不是 SaaS Dashboard。
- [ ] 主标题有识别度，但不支配整个首屏。
- [ ] 中性底色占据绝大多数面积，橙色只用于强调。
- [ ] 最近更新是首屏主要内容之一。
- [ ] 关系图只展示 Selection API 的真实概念关系。
- [ ] 页面不显示虚构百分比、阅读量或知识数量。
- [ ] 所有模块都能明确转换成响应式 HTML/CSS 布局。
- [ ] 视觉稿保存在版本化路径，评审结论写入决策日志。
