# Personal Knowledge Base Redesign — 决策日志

**关联 SPEC：** [`2026-07-17-personal-knowledge-base-redesign-design.md`](./2026-07-17-personal-knowledge-base-redesign-design.md)
**更新规则：** 新决策追加记录；不删除历史结论。被替代的决策标记为 `Superseded` 并链接新决策。

## DEC-001：站点定位为个人知识库

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 站点从以发布时间为中心的博客，演进为公开可阅读的个人知识库。博客保留为内容类型之一。
- **原因：** 当前内容已经包含学习笔记、问题梳理、工程实践和代码练习，只用分类与时间不足以表达这些内容之间的关系。
- **影响：** 首页、搜索、内容模型和详情页需要支持主题、状态、关联和学习路径。

## DEC-002：MDX 与 Git 继续作为事实来源

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 不因界面改造引入新的主数据库；写作工具最终仍写出仓库内 MDX，并通过 Git 追踪。
- **原因：** 当前内容和发布链路已经稳定，版本历史、审核和回滚都建立在 Git 上。
- **影响：** Writing Studio 属于 MDX 的编辑层，不是另一个内容系统。

## DEC-003：简洁与可视化同时成立

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 视觉元素只表达真实知识结构、学习进度、内容状态或导航关系；不使用纯装饰性“数据大屏”。
- **原因：** 用户希望页面简洁、有可视化元素，并高度重视整体美感。
- **影响：** 可视化组件必须有数据来源、交互作用和移动端降级方案。

## DEC-004：V1 概念图只保留内容结构

- **日期：** 2026-07-17
- **状态：** Superseded for visual execution
- **设计稿：** [`concept-v1.png`](./assets/knowledge-base-redesign/concept-v1.png)
- **保留：** 全局搜索、知识主题、最近更新、正在学习的首页内容结构。
- **否决：** 过大的 Hero 标题、常见 SaaS Dashboard 卡片、虚构数量与进度、缺少移动端策略、视觉语言不够精致。
- **下一步：** V2 先建立真实内容和排版基线，再探索编辑式、知识关系式两种构图。

## DEC-005：所有改造使用仓库内 SPEC 追踪

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 产品要求、UI 原则、设计稿版本、实现计划和验证结果都存放在仓库中并互相链接。
- **原因：** 避免关键判断只存在于聊天记录，也避免后续 Agent 重复推导或违背已确认方向。
- **影响：** 实现任务必须引用 SPEC 条目；设计稿不覆盖旧版本；被拒方案也保留原因。

## DEC-006：设计过程不依赖 Superdesign skill

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 已卸载 Superdesign skill，后续设计过程以仓库 SPEC、版本化视觉稿和用户评审为准。
- **原因：** 用户明确要求忘记并卸载该 skill。
- **影响：** 不创建或依赖 `.superdesign` 目录及其远端设计状态。

## DEC-007：Dribbble 是参考库，不是实现模板

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 从 Dribbble 提炼排版、网格、留白、色彩和信息可视化方法，但不复制具体作品。
- **原因：** 需要提高 UI 完成度，同时维持个人知识库的真实内容和可实现性。
- **影响：** 每个参考都记录“借鉴什么”和“不借鉴什么”，见视觉参考文档。

## DEC-008：浅色界面使用中性底色与橙色强调

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 弱化现有暖橙渐变，浅色页面以中性背景承担主要面积，橙色只用于焦点、状态、链接提示和少量品牌细节。
- **原因：** 用户接受推荐方向，希望简洁和美感同时成立。
- **影响：** V2 不再使用大面积橙色背景或多种竞争性强调色。

## DEC-009：首页使用编辑式骨架与局部知识关系图

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 首页首先是一张内容清晰的编辑式索引；知识关系图作为局部导航和视觉记忆点，不占据整个首屏。
- **原因：** 编辑式布局能保证可读性，局部可视化能体现知识库特征而不把页面变成 Dashboard。
- **影响：** V2 以最近更新、真实主题数据和一个局部关系图构成首屏主体。

## DEC-010：先定稿浅色版，再派生暗色版

- **日期：** 2026-07-17
- **状态：** Accepted
- **决定：** 当前设计和评审只覆盖浅色模式；浅色版视觉语言确认后，再建立对应暗色 SPEC 与设计稿。
- **原因：** 避免在核心层级和视觉语言尚未稳定时同时维护两套探索稿。
- **影响：** 浅色版验收不以暗色版完成为前提，但实现阶段仍需保留主题能力。

## DEC-011：V2 先以可回退首页切片进入实现

- **日期：** 2026-07-17
- **状态：** Accepted for experiment
- **决定：** 先实现浅色 V2 首页、简化导航、首页搜索接入与全局字体/画布，不同时迁移内容模型或改造完整站点。
- **原因：** 用户确认内容方向并希望直接试做，但 UI 仍需要在真实内容和真实交互中验证。
- **影响：** 现有 `/blog`、文章 URL、MDX 数据链路和主题能力继续保留；本轮不展示尚未实现的学习路径路由。实现范围与回退边界见 [`../plans/2026-07-17-personal-knowledge-base-home-light-v2.md`](../plans/2026-07-17-personal-knowledge-base-home-light-v2.md)。
