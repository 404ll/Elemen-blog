## 参考方法

参考作品用于回答以下问题：

1. 页面如何通过排版和网格建立高级感？
2. 可视化如何帮助理解，而不是制造噪音？
3. 知识索引如何同时支持扫描和探索？
4. 深色与浅色如何保持同一视觉性格？

每个参考都必须记录：

- 借鉴的原则。
- 不借鉴的表现。
- 可以映射到本站的具体页面。

## REF-001：Dribbble

- **链接：** <https://dribbble.com/>
- **用途：** 视觉完成度、构图和界面语言参考库。
- **边界：** 不把点赞量或流行风格当作可用性证据；不直接复刻作品。

## REF-002：Editorial Web Interface Design

- **链接：** <https://dribbble.com/shots/27324420-Editorial-Web-Interface-Design>
- **借鉴：** 强标题层级、模块化网格、少量强调色、内容优先的编辑式结构。
- **不借鉴：** 新闻门户式的信息密度和商业媒体模块。
- **本站映射：** 首页、知识索引、专题页。

## REF-003：Finding Clarity in the Uncharted

- **链接：** <https://dribbble.com/shots/26937275-Finding-Clarity-in-the-Uncharted-Minimal-Editorial-Web-Design>
- **借鉴：** 大面积留白、克制的单色关系、平静的阅读节奏。
- **不借鉴：** 只追求情绪而弱化导航和搜索的展示型布局。
- **本站映射：** 文章详情页、关于页。

## REF-004：Knowledge Graph

- **链接：** <https://dribbble.com/shots/16447244-Knowledge-graph>
- **借鉴：** 节点大小、连线、层级与导航辅助可以同时编码信息。
- **不借鉴：** 首屏展示数千节点、持续运动或需要复杂手势才能使用的图谱。
- **本站映射：** 主题关系、文章关联、学习路径；第一阶段仅使用小型局部图。

## REF-005：Node — Blog Web Design

- **链接：** <https://dribbble.com/shots/25990996-Node-Blog-Web-Design>
- **借鉴：** 技术内容的清晰分组、日期/标签/摘要层级、深色模式中的柔和边框。
- **不借鉴：** 通用紫色科技渐变、所有内容都装进同类卡片。
- **本站映射：** 知识列表、暗色模式、首页精选内容。

## REF-006：Knowledge Base Design

- **链接：** <https://dribbble.com/shots/6924767-Knowledge-Base-Design>
- **借鉴：** 搜索是知识库第一入口；关键操作通过清楚对比获得注意力。
- **不借鉴：** 客服帮助中心的 FAQ 分类结构和工单导向。
- **本站映射：** 首页搜索、知识索引空状态和快速入口。

## REF-007：Personal Knowledge Management App UI Concept

- **链接：** <https://dribbble.com/shots/10498867-Personal-Knowledge-Management-App-UI-Concept>
- **借鉴：** 个人知识管理工具可以同时体现内容状态与关系。
- **不借鉴：** 将公开阅读站点做成高密度后台 Dashboard。
- **本站映射：** 本地 Writing Studio，而不是公开文章详情页。

## 统一结论

下一版视觉稿需要同时满足：

- 首页拥有一个清楚的视觉记忆点，但不能依赖巨大标题。
- 搜索、最近更新、主题和学习路径的层级一眼可辨。
- 正文页比首页更安静。
- 可视化只使用真实数据。
- 公开页面不像后台 Dashboard，写作工作台也不伪装成内容网站。
- 桌面和移动端都必须出稿，不能把移动端视为自动换行。

## 禁止模式

- 大面积玻璃拟态。
- 每个模块使用不同渐变。
- 无真实数据来源的图表和百分比。
- 知识图谱作为唯一导航。
- 全站统一大圆角卡片。
- 只为截图好看、实际无法实现或无法响应式适配的布局。
